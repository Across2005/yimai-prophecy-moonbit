## 1. 安全审计 (P10 delta)

### 1.1 `is_safe_origin` IPv6 解析 bug (P9 隐藏) ✅ 已修

**位置**: `cmd/service/routes.mbt` P9 commit (L236-251)

**问题**: P9 加的 IPv6 检查 `host.has_prefix("[::1]")` 实际**永远 false**:
- 输入 `http://[::1]:8787` → `hostport = "[::1]:8787"`
- `hostport.split(":")` = `["[", "", "1]", "8787"]`
- `host = "["`, `host.has_prefix("[::1]")` = false
- → IPv6 环路 origin **被误拒** (保守但不兼容)

**影响**: 当前服务绑 `127.0.0.1:8787` (IPv4 only) 不会被实际触发 (请求根本到不了),
但若未来绑 `0.0.0.0` 或启用 IPv6 双栈, 该 bug 会让本地 `[::1]` 浏览器客户端被 403。
属"提高兼容性"范畴的潜在缺口, P10 修。

**修复**: 抽出 `is_loopback_hostport`, 显式处理 `[host]:port` 形式:
```moonbit
fn is_loopback_hostport(hostport : String) -> Bool {
  if hostport.length() == 0 { return false }
  if hostport[0] == '[' {
    // IPv6 形式 — 找配对的 ']'，取内部内容
    let chars = hostport.iter().to_array()
    let mut end = -1
    for i = 0; i < chars.length(); i = i + 1 {
      if chars[i] == ']' { end = i; break }
    }
    if end <= 0 { return false }  // 缺 ']' 或 '[]' 空内容
    let inner = hostport[1:end].to_owned()
    inner == "::1"
  } else {
    // IPv4 / 主机名 :port
    let host = hostport.split(":").to_array()[0]
    host == "127.0.0.1" || host == "localhost"
  }
}
```

**验证**: 0 警告 (native + wasm-gc) + 175/175 测试全绿 (覆盖路由表 / MCP / REST / 静态服务)。

| 文件 | 行数 | 主题 |

| `engine_consolidate.mbt` | 237 | consolidate 4 段 + restore + WAL 增量日志 (D6 + #21) |

| `engine_ops.mbt` | 518 | style/back_align/term_conflicts/retrieve_for_prompt + 主动学习/联邦/蒸馏/可观测 |

**为什么全部在根目录** (而不是 `src/lib/engine_*.mbt`):
- MoonBit 0.1.20260724 限制: sub-package 间不能互相 import 主包符号 (`@lib.X`)
- 根 `moon.pkg` 即根包, `@lib` 别名指向它
- 同目录多 `.mbt` 文件自动 include 到同一包, 调用点零修改
- 这是 MoonBit 限制下"尽量以代码打包进文件夹的形式编程"的正确落地: 主题分组到独立
  `.mbt` 文件, 减少单文件体积, 但不破坏包边界

**复现脚本**: `scripts/split_engine.py` (一次性脚本, 不入仓库正式 scripts/)

**验证**: 175/175 wasm-gc + 0 警告双 target + 13/13 harness 全绿

### 2.2 root lib 大文件为何留在根目录 (P9 已声明, P10 重申)

- MoonBit 0.1.20260724 限制: sub-package 间不能互相 import 主包符号
- `engine.mbt` / `util.mbt` / `yimai_prophecy_moonbit.mbt` 是根 package 源文件, `@lib` 别名

## 4. 国际翻译/标准前沿更新

### 4.1 ISO 17100 → ISO/AWI 17100 (修订立项)

`ISO/AWI 17100` 于 **2025-07-22** 立项 (stage 20.00 "New project registered in TC/SC work programme",
ISO/TC 37/SC 5)。预期话题: MT/AI 整合 / second pair of eyes 范围 / 与 ISO 18587 合并可能 /
能力要求去 Eurocentric。**当前 ISO 17100:2015 + Amd 1:2017 仍为正式版**, yimai 映射保持。

### 4.2 EU AI Act Article 50(2) — 机器翻译明确豁免

**Commission Guidelines C(2026) 5054 final** (2026-07-20) 在 standard-editing 豁免清单
**明文列入** "AI-generated translations of text" — MT 输出**通常不触发** provider 端
机器可读标注义务。`MQM Council RFC-1-20260802` (DOI 10.5281/zenodo.21765333) 同步
给出与 Commission 一致的解读。罚则: EUR 15M 或全球年营业额 3%。

yimai 作为本地引擎不代行标注; adopter 在欧盟公利益场景部署时需自补标注层。
**Article 50(4) deployer 端披露义务** 在公利益文本场景独立成立 (除非有 substantive
human review / editorial responsibility), 译文不自动继承源文编辑清关。

### 4.3 MCP 2026-07-28 稳定版 — yimai 维持 2025-11-25 (不变)

`2026-07-28` 已正式发布 (2026-07-28): 无状态核心 + `Mcp-Method`/`Mcp-Name` 头 +
`Mcp-Session-Id` 移除 + OAuth 2.1 / RFC 9207 issuer 校验 + Roots/Sampling/Logging
deprecation 12 个月窗口 + 错误码 -32002 → -32602。

**yimai 决策: 维持 2025-11-25** (与 P9 一致)。理由: 纯本地、绑 `127.0.0.1`、无鉴权;
13 个 harness 均基于 2025-11-25 `initialize` 握手消费; spec 明确"仅本机 stdio / 无远程扩容"
场景可暂不升级。迁移 0.2.0 视 adopter 需求评估 (dual-era 兼容优先)。
